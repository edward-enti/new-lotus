# Phase 3 security note — for Supervisor approval BEFORE Phase 3 starts

Short table only (PLAN §6). Proposed values are proposals: Phase 3 must not
start until the Supervisor approves them here.

| Area | Minimum default (proposed) |
|---|---|
| Admin credentials | From `ADMIN_USER` / `ADMIN_PASSWORD` env vars only. No default credential in code, `.env.example`, or config defaults. At startup, hash the env password with bcrypt (cost 12) into a memory-only value and verify logins by hash comparison only — never compare, log, or ship a plaintext password. Server refuses to start, and the login handler refuses login, when either env var is missing or empty (fail closed). |
| Sessions | `crypto/rand` 32-byte token. Server stores only SHA-256(token) (DB session row: token hash, expiry, created_at). Cookie: `HttpOnly`, `SameSite=Lax`, `Path=/admin`, `Secure` when `APP_ENV=production`. Expiry: 12 hours. Rotation on login (new token, old row deleted). Invalidation on logout (row deleted). |
| Auth coverage | Every `/admin/*` handler (pages, POSTs, upload, status changes) requires a valid admin session, except login GET/POST themselves. Unauthenticated `/admin/*` access redirects (302) to `/admin/login`. |
| Login hardening | Generic failure error only — “Tên đăng nhập hoặc mật khẩu không đúng” — for both unknown user and wrong password (no user-vs-password oracle). Login rate limiting REUSES the existing IP limiter mechanism (same code as the inquiry limiter): 5 failed attempts per 15 minutes per IP, then 429. |
| CSRF | Required on ALL state-changing POSTs: login, admin CRUD, upload, inquiry status changes, and the public inquiry form. Admin/session forms: synchronizer token stored server-side in the session, compared in constant time. Public inquiry form (no session): double-submit cookie token + hidden field, compared for equality. Rejection: 403. Tested in Gate 3. |
| Uploads | Admin session + CSRF required. Allowlist: images (`.jpg`, `.jpeg`, `.png`, `.webp`, `.gif`) + `.pdf` only. Size cap enforced with `http.MaxBytesReader`: **10 MB per file**. Filename sanitised to a safe basename (`media_service.SanitizeFilename`: no `..`, no path traversal). `/uploads/*` serves with `X-Content-Type-Options: nosniff`, no directory listing, `Content-Disposition: inline` with the sanitised filename for allowed types only; `.html` / `.svg` / `.js` are rejected at upload and never servable (non-allowlisted extensions return 404 from `/uploads/*`). |
| Security headers (explicit set, applied by security middleware) | `X-Content-Type-Options: nosniff`; `Referrer-Policy: strict-origin-when-cross-origin`; `X-Frame-Options: DENY`; `Permissions-Policy: camera=(), microphone=(), geolocation=()`; `Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; frame-ancestors 'none'` — `'unsafe-eval'` is required because Alpine.js evaluates expressions, and `'unsafe-inline'` styles because Alpine `:style` sets inline styles; this trade-off is stated here rather than hidden, and an Alpine CSP build is a Phase 4 consideration, not a Phase 3 change. `Strict-Transport-Security: max-age=31536000; includeSubDomains` only when served over HTTPS in production (never forced on plain-HTTP local dev). |
| Middleware order (fixed) | recovery → logging → security headers → redirect → rate limit → admin auth → CSRF. |
| Other standing rules | Parameterised SQL everywhere. Never log passwords, session tokens, phone numbers, emails, or other PII/secrets. Inquiry form keeps the `website_url` honeypot and the RemoteAddr-based IP limiter from Phase 2. |
